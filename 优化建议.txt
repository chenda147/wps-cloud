============================================
WPS 追更 + 下载 优化建议清单
============================================
说明：每完成一项，将该项状态改为 [x] 并在下方"完成备注"中注明
完成时间与改动内容。对照对象：MoviePilot、AutoFilm 等成熟项目。

【优先做】★ = 建议优先处理（直接影响"不好用"的体感）

------------------------------------------------------------
一、追更侧
------------------------------------------------------------

★ 1. 追更检查历史结构化
    状态：[x] 已完成
    描述：目前卡片只有一行 last_result 字符串，看不出每次检查
    发现了哪几集、哪些下载成功/失败、耗时。建议新增 chase_history
    列表（时间、发现的新集、结果、耗时、错误信息），卡片可展开查看最近 N 次。

★ 2. 失败原因感知与预警
    状态：[x] 已完成
    描述：记录"最后成功时间"，超过阈值标黄预警；错误归类为可操作
    文案（如"Cookie 失效，请更新配置"），并支持自动重试 + 指数退避。

★ 3. 通知推送
    状态：[x] 已完成
    描述：追更到新集 / 下载完成 / 任务失败，推送到微信 / Server酱 /
    Telegram。没有通知，用户每天都要开网页看，追更闭环缺失。

★ 4. 创建追更时支持"测试/预览"
    状态：[x] 已完成
    描述：保存前先预览分享目录里能匹配到的文件列表，验证链接有效性
    与正则正确性，避免建完才发现抓不到。

5. 智能调度（按剧集更新周期）
    状态：[x] 已完成
    描述：统一轮询所有追更改为按剧集频率配置检查间隔/时间段，或按
    上次更新时间自适应，节省 API 配额并避免错过。

------------------------------------------------------------
二、下载侧
------------------------------------------------------------

★ 6. 断点续传与任务恢复
    状态：[x] 已完成
    描述：客户端重启/断网后任务可恢复，临时文件 + 完成后改名，
    同名文件不重复下载。

★ 7. 下载进度可见
    状态：[x] 已完成
    描述：任务带 progress / speed / stage（检查/下载/上传）字段，
    客户端心跳上报，界面实时渲染进度条、速度、剩余时间。

★ 8. 上传 WPS 后校验 + 重名策略
    状态：[x] 已完成
    描述：本地文件大小 vs WPS 返回大小比对；重名文件策略
    （跳过 / 覆盖 / 自动改名）。

9. 多客户端任务竞争处理
    状态：[x] 已完成
    描述：客户端心跳 / 最后在线时间，派任务跳过离线客户端，
    卡住的任务标记失败并告警，避免指定客户端离线后任务永远挂起。

------------------------------------------------------------
三、客户端（移动端）
------------------------------------------------------------

★ 10. 移动端可操作化
     状态：[x] 已完成
     描述：移动端目前只有 Settings/Tasks/Logs，是"哑终端"。补上
     追更列表、手动检查、下载管理操作，追更场景主要靠手机。

★ 11. 日志页可用性
     状态：[x] 已完成
     描述：日志支持级别过滤 / 搜索 / 错误高亮，便于排障。

------------------------------------------------------------
四、健壮性
------------------------------------------------------------

12. 正则规则"测试工具"
    状态：[x] 已完成
    描述：后台粘贴文件名 → 测试是否命中规则，减少配置试错成本。

13. 幂等与去重
    状态：[x] 已完成
    描述：chase_done 重复上报不重复生成 STRM；任务领取加锁 / 状态机
    （pending→running→done），避免多客户端同时领取同一任务。

14. 存储健壮性
    状态：[x] 已完成
    描述：JSON 文件存储加写锁 / 原子写，避免并发读写丢数据；
    长远可迁移 SQLite。

    请求头直接返回 200 全量内容时，原代码仍用 "ab" 模式追加，会把已下载
    部分与全量内容拼接导致文件损坏；现改为检测到 status 200 且已有部分

  - 临时文件机制：下载先写 <name>.part，完成后 os.replace() 原子改名成
    最终文件名，避免半成品被误当成品（如被清理逻辑删除/被工具扫描到）。
    · 最终文件已存在且大小达标 → 直接跳过（不重复下载）
    · .part 存在 → 从已下载字节续传
    · .part 大于源文件大小（分享链接被更新过）→ 丢弃残留重新下载
    · .part 恰好下载完但上次未及改名（进程中途退出）→ 补做改名
  - 兼容性：调用方拿到的 local_path 仍是最终路径（改名后返回），archive
    解压、上传、删除等下游逻辑无需改动；旧版遗留的直接文件名半成品会在
    重下后被覆盖清理。
